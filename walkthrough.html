PROJECT COMPOSITION

How the Code is Structured

QuizPulse is designed with 100% semantic HTML5, CSS3, and vanilla JavaScript following The Odin Project Foundations principles. There are no npm build tools, no React/Vue frameworks, and no complex module loaders.

File Name Type Core Purpose & Responsibility
index.html HTML + CSS Landing page presenting two distinct paths: Organizer Sign In / Sign Up, and Student 6-Digit Room Code entry.
teacher.html HTML + CSS Faculty dashboard for managing quizzes, validating JSON specifications, launching live rooms, and inspecting candidate performance.
student.html HTML + CSS Candidate check-in page with username/password validation and a synchronized waiting room that listens for room start.
quiz.html HTML + CSS Live examination interface with fullscreen lockdown, countdown timers, autosaved answer drafts, and visibility-controlled results.
firebase.js JavaScript Isolated Firebase config. Creates the global db (Firestore) and auth instances with an automatic offline fallback.
auth.js JavaScript Backend queries for organizer accounts (1 account per email), student sessions, past quiz fetching, and class statistical analysis.
app.js JavaScript The examination engine: builds question cards, drives the countdown timer, monitors 1-strike anti-cheat, grades submissions, and purges sessions.
vercel.json JSON Deployment configuration enabling clean URLs (e.g. /teacher instead of /teacher.html).
SCRIPT LOADING PIPELINE

How Scripts Connect in Each Page

Each page loads only the scripts it requires in a strict sequential order via standard HTML <script> tags:

Firebase Compat CDN ──► firebase.js ──► auth.js ──► app.js (quiz.html only) (Google Cloud SDK) (Config & db) (Data & Auth) (Active Exam Engine)

Because no ES modules are used, all variables are shared cleanly and predictably through standard browser scope.

STEP-BY-STEP WORKFLOW

The Organizer Workflow

1
Account Creation & Sign In
Teachers register directly with their email and password on index.html. No verification emails are sent or required. The system strictly enforces one account per email by checking Firestore before registering.
2
Faculty Dashboard
Upon login, the teacher sees their overview dashboard with metric cards (Total Quizzes, Active Rooms, Total Submissions, and Class Average) and a table of all quizzes created by them, sorted newest first.
3
JSON Assessment Creator
Clicking "+ Create New Quiz" opens a large JSON editor with a sample loader. Clicking "Verify Schema" inspects every question, option, timer, and answer key. Only when the schema is 100% valid is the "Save & Generate Code" button unlocked.
4
Live Room Control Room
Saving generates a unique 6-digit room code (e.g. 482910). In the Control Room:
  • Start Quiz: Changes status from waiting to active, triggering the student entry timer.
  • End Quiz: Instantly auto-submits all active student exams and seals the room.
  • Post-Quiz Visibility Selector: Changes between marks_only, marks_and_answers, and full_analysis in real time.
5
Student Drill-Down & Analytics
Teachers can click on any candidate to inspect their complete attempt: the question prompt, what the student marked, the official correct answer, time spent on each question, and whether an anti-cheat violation occurred.
STEP-BY-STEP WORKFLOW

The Candidate (Student) Experience

1
Room Code & Credentials Check-In
The candidate visits student.html (or clicks a direct link like student.html?code=482910). They type their Student ID. By system rule, the password automatically matches the Student ID.
2
Synchronized Waiting Lobby
The student is placed in the waiting room with animated pulse dots. A background poller checks Firestore every 2 seconds. The moment the teacher clicks "Start Quiz", the waiting room activates.
3
Timer 1: Entry Window Countdown
Once the room is active, a countdown shows remaining entry time (e.g. 5 minutes). If the student fails to click "Enter Quiz Now" before this timer hits zero, entry is permanently locked with an "Entry Window Closed" screen.
4
Active Assessment Screen (quiz.html)
The exam requests fullscreen. The attempt duration timer (Timer 2) begins counting down. Selecting options automatically saves an answer draft to sessionStorage and Firestore so progress is never lost on refresh.
5
Results View & Session Purge
Upon submission (manual or automatic), results appear strictly based on teacher visibility settings. Clicking "Log Out & Exit" marks sessionPurged: true in Firestore, permanently locking the candidate from retaking the assessment.
EXAMINATION INTEGRITY

1-Strike Anti-Cheat Architecture

To prevent candidate dishonesty, app.js arms 6 silent background listeners when the exam begins. There are no warnings or counters: the exam terminates immediately upon the first infraction.

Detection Mechanism Browser Event System Action
Tab Switching visibilitychange (document hidden) Instant Auto-Submit (terminated_cheat)
Window Focus Loss window.blur Instant Auto-Submit (terminated_cheat)
Exiting Fullscreen fullscreenchange (fullscreenElement == null) Instant Auto-Submit (terminated_cheat)
Right Click Context Menu contextmenu (event.preventDefault()) Instant Auto-Submit (terminated_cheat)
Copy Attempt copy (event.preventDefault()) Instant Auto-Submit (terminated_cheat)
Paste Attempt paste (event.preventDefault()) Instant Auto-Submit (terminated_cheat)
DUAL SYNCHRONIZED TIMERS

How the Timers Operate

T1
Timer 1: Entry Window (entryWindowSeconds)
Counts down from the moment the organizer clicks "Start Quiz" (quizStartTimestamp). Ensures that latecomers cannot enter the assessment after the designated join period closes.
T2
Timer 2: Attempt Duration (attemptDurationSeconds)
Counts down the candidate's allowed exam time. Turns red when under 60 seconds remain. When it reaches 00:00, the assessment automatically calculates the score and seals the submission.
DATA ARCHITECTURE

Cloud Firestore Schema

Data is stored in Google Cloud Firestore under two clean collections:

Collection Document ID Stored Fields
organizers Teacher's email email, name, password, createdAt
quizzes 6-digit room code (orgId) orgId, quizTitle, status (waiting|active|ended), entryWindowSeconds, attemptDurationSeconds, postQuizVisibility, questions[], answerKey{}, submissions[]
